
## JTAG：
### 1. JTAG 是什么？

- **JTAG** 是 **Joint Test Action Group** 的缩写，最初是一个由半导体行业专家组成的组织，后来其工作成果被 IEEE 采纳，成为 **IEEE 1149.1 标准**，正式名称是 **“Test Access Port and Boundary-Scan Architecture”（测试访问端口和边界扫描架构）**。
    
- **目的：** JTAG 最初设计的主要目的是为了**测试印刷电路板（PCB）上集成电路的互连和内部功能**，特别是在电路板日益复杂，传统探针测试难以进行的情况下。它允许通过少量引脚（通常是四个）对芯片内部进行“透视”和控制。
    
- **串行接口：** JTAG 是一种**串行接口**，这意味着数据是逐位传输的，而不是同时传输多个位。这使得它所需的引脚数量非常少。
    
---

### 2. JTAG 在 FPGA 配置中的应用

虽然 JTAG 最初用于测试，但其能够访问和控制芯片内部寄存器的特性使其成为 FPGA 配置的理想选择。

- **比特流传输：** FPGA 的配置过程就是将比特流数据写入其内部的配置内存。JTAG 提供了一种将这些比特流数据从外部（例如通过 USB 连接的 JTAG 编程器）传输到 FPGA 的方式。
    
- **命令封装：** 要通过 JTAG 接口发送配置命令，这些命令必须符合 JTAG 的协议，即被封装在特定的 **JTAG 命令头和尾**中。这是因为 JTAG 有一个定义好的**状态机协议**，需要通过一系列的移位、捕获、更新等状态转换来正确地访问和操作芯片内部的**JTAG 寄存器**。这些寄存器是 JTAG 机制与芯片内部功能（包括配置模块）进行交互的桥梁。

---

### 3. JTAG 的主要优势

- **硬件内置和引脚少：**
    
    - **“JTAG hardware ports are already built into almost all Xilinx FPGA boards”：** 这是 JTAG 普及的关键。大多数 FPGA 芯片和开发板都原生支持 JTAG 接口，无需额外设计专用接口。
        
    - **“using JTAG only requires the use of those four pins”：** JTAG 标准定义了四个强制引脚（TDI, TDO, TCK, TMS）和一个可选的复位引脚 (TRST)。这种极少的引脚数量大大简化了 PCB 设计，降低了硬件成本，并方便了调试和编程。
        
        - **TDI (Test Data In)：** 测试数据输入。
            
        - **TDO (Test Data Out)：** 测试数据输出。
            
        - **TCK (Test Clock)：** 测试时钟。
            
        - **TMS (Test Mode Select)：** 测试模式选择。
            
        - **TRST (Test Reset)：** 测试复位（可选）。
            
- **优先级最高：**
    
    - **“JTAG is also the highest priority configuration interface”：** 这意味着无论 FPGA 的其他配置模式引脚（通常用于选择主/从串行、并行等配置模式）如何设置，JTAG 接口始终可以访问 FPGA 的**配置模块**。这在调试或配置失败时尤其重要，JTAG 提供了“最终手段”来控制和检查 FPGA 的状态。
        
- **通用性和调试能力：**
    
    - **多设备编程：** JTAG 链允许将多个支持 JTAG 的芯片（不限于 FPGA，可以是微控制器、ASIC 等）串联起来，通过一个 JTAG 端口进行统一的编程和测试。
        
    - **边界扫描：** 这是 JTAG 的核心功能之一，允许在芯片的引脚（边界）处进行数据捕获和控制，极大地简化了 PCB 级故障诊断。
        
    - **片上调试 (On-Chip Debugging)：** JTAG 接口也是连接到 FPGA 内部调试工具（如 Xilinx Vivado 的 ILA/VIO）的常用方式，允许开发者实时观察和控制 FPGA 内部信号，进行硬件调试。

---
### 4. 局限性

- **串行链编程：**
    
    - **“must do so in a serial chain, (not in parallel like SelectMAP)”：** 这是 JTAG 相较于一些并行配置接口（如 SelectMAP）的缺点。虽然可以编程多个设备，但数据是串行传输，对于单个设备或需要快速配置的场景，其配置速度可能不如并行接口。
        
    - **SelectMAP：** 这是一个并行配置接口，通常使用更多引脚，但可以以并行方式（一次传输多个比特）进行数据传输，因此速度更快。
        
- **速度限制：**
    
    - **“typically accessed from an external source, with clock rates up to 66 MHz”：** 66 MHz 的时钟速率对于配置大型 FPGA 来说，可能需要一定的时间。然而，对于大多数调试和单次配置而言，这个速度通常是足够的。

## SelectMAP

### 1. SelectMAP 是什么？

SelectMAP 是 Xilinx FPGA 提供的一种**并行配置接口**。与串行的 JTAG 接口不同，SelectMAP 的设计目标是实现**高速、大容量的配置**。

- **并行 (Parallel)：** 这是 SelectMAP 的核心特点。它意味着数据不是逐位传输，而是多位同时传输。
    
- **高带宽 (High-bandwidth)：** 由于并行传输，SelectMAP 在单位时间内能够传输更多的数据，因此具有更高的带宽。
    
- **双向数据总线 (Bi-directional data bus)：** 这表明数据可以在两个方向上流动（输入到 FPGA 进行配置，或者从 FPGA 读取配置状态/数据）。
    
- **支持数据宽度：** 可以配置为 8、16 或 32 位的数据宽度。数据宽度越大，一次传输的数据量就越多，配置速度也就越快。

---

### 2. SelectMAP 的主要优势

文章提到了 SelectMAP 的两个主要优势：

- **并行配置多个 FPGA (Configure multiple FPGAs in parallel)：**
    
    - 在一些大型系统中，可能需要使用多个 FPGA。SelectMAP 允许这些 FPGA 同时（并行）进行配置，而不是像 JTAG 那样必须串联依次配置。这对于需要快速启动的大规模 FPGA 系统来说，是一个巨大的优势，可以显著缩短上电后的系统启动时间。
        
- **高速时钟速率 (High-speed clock rates up to 100 MHz)：**
    
    - 高达 100 MHz 的时钟速率意味着数据传输的速度非常快。结合其并行的数据宽度，SelectMAP 能够提供极高的配置吞吐量。这对于那些需要频繁重配置 FPGA 或者配置大容量 FPGA 的应用场景至关重要。

---

### 3. SelectMAP 的主要缺点

文章明确指出了 SelectMAP 的一个关键缺点：

- **占用 I/O 引脚 (Occupies I/O pins)：**
    
    - **“a number of I/O pins (equal to the data bus length) must be reserved during configuration by SelectMAP, and thus are temporarily not available to the user design.”**
        
    - 这是并行接口固有的特性。为了实现 8、16 或 32 位的数据宽度，就需要对应数量的 I/O 引脚（加上控制引脚，总数更多）。在 FPGA 配置完成之前，这些引脚都被 SelectMAP 接口占用，不能被用户设计的逻辑使用。
        
    - **影响：** 对于引脚资源紧张的 FPGA 设计来说，这是一个重要的权衡点。开发者需要牺牲一部分宝贵的通用 I/O 引脚，来换取更快的配置速度。一旦配置完成，这些引脚通常可以被用户设计重新利用（即它们是“暂时”不可用），但这要求用户设计必须等待配置完成后才能激活这些引脚的功能。

---
### 4. SelectMAP 与 JTAG 的对比与选择

SelectMAP 和 JTAG 是 FPGA 常见的两种配置接口，它们各有侧重：

|特点|**SelectMAP**|**JTAG (IEEE 1149.1)**|
|---|---|---|
|**数据传输**|**并行**（8/16/32 位数据宽度）|**串行**（逐位传输）|
|**配置速度**|**高带宽，速度快**（高达 100 MHz 时钟）|相对较慢（最高 66 MHz 时钟，且为串行）|
|**I/O 占用**|**需要占用大量 I/O 引脚**（等于数据总线宽度）|**只需要 4-5 个专用引脚**|
|**多设备配置**|**并行**配置多个 FPGA|**串联链式**配置多个 JTAG 兼容设备|
|**主要用途**|**高速大规模配置、多 FPGA 同步配置**|**调试、测试、单设备或少量设备配置、故障诊断**|
|**优先级**|较低（相对于 JTAG，JTAG 通常是最高优先级）|**最高优先级配置接口**|
|**灵活性**|更专注于快速配置|兼顾配置与强大的片上测试/调试能力|

---
### 拓展应用场景

- **高速原型验证系统：** 当需要快速验证大型 ASIC 设计时，通常会使用多个 FPGA 组成原型验证板，SelectMAP 的并行配置能力可以大大缩短每次设计迭代的配置时间。
    
- **高性能计算：** 在一些高性能计算应用中，FPGA 可能需要根据不同的任务负载进行动态重配置。SelectMAP 提供的高速配置能力可以支持这种快速的“上下文切换”。
    
- **启动时间敏感设备：** 对于一些对启动时间有严格要求的设备（例如某些通信设备或医疗设备），SelectMAP 能够确保 FPGA 尽快进入工作状态。
    

总而言之，SelectMAP 是为追求**极致配置速度和并行化配置**而设计的接口，其代价是需要占用更多的 I/O 引脚。在选择配置接口时，开发者需要根据自己的具体应用需求（如配置速度要求、可用 I/O 数量、是否需要片上调试功能等）来权衡选择最合适的方案。

## ICAP2
### 1. ICAP 是什么？

ICAP 是 **Internal Configuration Access Port** 的缩写，顾名思义，它是一个位于 FPGA **内部**的配置接口。与 JTAG 和 SelectMAP 这些通常从 FPGA 外部进行配置的接口不同，ICAP 允许 FPGA 内部的**用户逻辑（即你自己设计的电路）**来控制对 FPGA 配置内存的读写。

- **内部访问：** 这是 ICAP 最显著的特点。它不是通过外部引脚连接到编程器，而是作为 FPGA 内部可实例化和访问的 IP 核或原语存在。
    
- **用户设计控制：** 你的 HDL 代码（如 Verilog 或 VHDL）需要实例化一个 ICAP 原语（一种特殊的、预定义的硬件模块），然后通过编程来控制这个原语，从而实现对 FPGA 自身的配置操作。
    
- **无法初始配置：** 文章明确指出，ICAP **无法执行初始配置**。这意味着 FPGA 必须先通过 JTAG、SelectMAP 或其他外部方式完成首次配置（即载入启动程序），然后才能利用 ICAP 进行后续的重新配置。

---
### 2. ICAP 的主要功能与优势

- **设备自重配置 (Device Self-Reconfiguration)：** ICAP 允许 FPGA **“自己配置自己”**。这意味着 FPGA 可以根据运行时的需求，动态地改变自身的硬件功能。
    
- **部分重配置 (Partial Reconfiguration, PR)：** 这是 ICAP 最主要的应用场景。部分重配置允许 FPGA 在不中断整体系统运行的情况下，动态地更改芯片内部的**一部分**逻辑功能。这就像给运行中的电脑更换一块显卡，而不用重启整个系统。
    
- **高配置速度：** 像 SelectMAP 一样，ICAP 也是一个高速并行接口，工作频率可达 100 MHz。这使得它能够快速地加载新的比特流片段，实现实时的功能切换。
    
- **“内部数据清理器（Scrubber）的首选接口”：** 这一点非常重要。Scrubber 是一种用于检测和纠正 FPGA 配置内存中由于单粒子翻转 (SEU) 等软错误而导致的数据错误的机制。ICAP 允许用户设计在 FPGA 运行时周期性地读取配置内存，检查数据完整性，并在发现错误时立即写回正确的数据，从而提高系统的可靠性。

---

### 3. ICAP 如何实现动态重配置？

ICAP 实现动态重配置的关键在于其作为内部接口，能够**在 FPGA 运行时访问和修改配置内存**。

1. **初始配置：** 首先，FPGA 通过外部接口（如 JTAG 或 SelectMAP）完成一次完整的初始配置。此时，芯片内部的逻辑单元和互联资源被编程，形成了一个初始的工作电路，其中也包含了控制 ICAP 的用户逻辑。
    
2. **用户逻辑控制 ICAP：** 在用户设计中，你会实例化 ICAP 原语，并编写相应的逻辑来控制它。这个逻辑可以包括：
    
    - **触发器和控制器：** 当满足特定条件时（例如，收到外部指令、达到某个时间点、检测到某个事件），控制器会激活 ICAP。
        
    - **数据源：** 用于重配置的比特流数据（称为 **partial bitstream，部分比特流**）可以存储在 FPGA 内部的 Block RAM 中，或者通过其他数据接口（如 PCIe、以太网）从外部加载到 FPGA 内部的缓存中。
        
    - **ICAP 读写操作：** 用户逻辑通过 ICAP 接口向配置内存写入部分比特流数据，或者读取配置内存中的数据（用于数据清理等）。
        
3. **重配置区域：** 在进行部分重配置时，FPGA 芯片被划分为多个区域：**静态区域 (Static Region)** 和 **可重配置区域 (Reconfigurable Region)**。
    
    - **静态区域：** 这部分逻辑在重配置过程中保持不变，继续正常运行。
        
    - **可重配置区域：** 这部分区域的逻辑将被 ICAP 写入新的比特流数据，从而改变其功能。
        
    - **重点：** ICAP 在修改可重配置区域时，**通常不会影响静态区域的运行**。这是实现“动态”和“不影响正在运行的程序”的关键。

---

### 4. 此时 FPGA 正在运行的程序不会被影响吗？为什么？

**大部分情况下，部分重配置不会影响 FPGA 正在运行的程序（即静态区域的逻辑）。**

**为什么？**

1. **区域隔离：** Xilinx FPGA 的架构设计支持物理上的区域隔离。静态区域和可重配置区域之间通过严格的**边界**进行分隔。这些边界是设计者在布局布线时定义的，确保了数据和控制信号不会从重配置区域“泄漏”到静态区域，反之亦然。
    
2. **门控时钟和隔离：** 当一个可重配置区域进行重配置时，其内部的时钟通常会被门控或暂停，以防止不确定状态的产生。同时，可重配置区域与静态区域之间的信号接口会通过特殊的**隔离电路 (Isolation Circuits)** 进行管理，确保在重配置过程中，无效或不稳定的信号不会传递到静态区域，从而干扰其正常运行。
    
3. **比特流目标明确：** 部分比特流只包含修改特定可重配置区域的信息。配置模块在处理这些比特流时，只会更新对应区域的配置内存，而不会触及静态区域的配置信息。
    
4. **硬件管理：** ICAP 以及其背后的配置逻辑是硬件实现的，它们的设计确保了原子性（atomic）的配置操作。当一个区域被重配置时，配置控制器会按照精确的步骤进行，避免对其他区域造成意外影响。

**然而，需要注意的例外情况和复杂性：**

- **设计挑战：** 虽然原理上不影响，但要设计一个能够成功进行部分重配置且不影响静态区域运行的系统，对开发者来说是复杂的。需要非常小心地管理静态区域和可重配置区域之间的接口，确保数据同步、时序正确，并处理好边界信号的隔离。
    
- **影响接口：** 如果可重配置区域与静态区域共享公共的 I/O 引脚或重要的内部总线，那么在重配置过程中，这些共享资源可能会短暂地受到影响，可能导致数据中断或延迟。设计者需要有策略地处理这些共享资源。
    
- **整个芯片重配置：** 如果使用 ICAP 进行**完整芯片重配置**，那么整个 FPGA 都会被清除并重新加载比特流，这将**中断所有正在运行的逻辑**，与初始配置无异。部分重配置才是其不中断运行的精髓。
    

总而言之，ICAP 是 FPGA 实现高度灵活性的强大工具，特别是通过**部分重配置**技术，使得 FPGA 能够像软件一样在运行时加载或更换功能，而不会中断整个系统的运作。这在很多需要动态适应、功耗优化或高可靠性的高级应用中具有巨大价值。
